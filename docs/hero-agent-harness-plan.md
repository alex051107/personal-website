# Home Hero — Agent Harness Plan

## Decision

This plan supersedes the selected direction in `hero-3d-scene-plan.md`. The old
nine images remain as versioned experiments, but the rail / gate / drawer
metaphor is no longer the intended Hero.

The new Hero is a **readable Agent Harness**, anchored to Dynamics Atlas because
that is the portfolio's actual Agent project. It shows one specific route:

`TaskPacket + molecular datasets -> Locator Agent -> registered tools -> six compatibility checks -> EvidenceBundle or block -> human review`

The visual does not claim that every project is an Agent. The same outer frame
can later expose three additional workflow profiles in HTML, with the Agent
station visibly inactive when the project is a model, ML workflow, or bounded
AI worker.

## Why the previous scene failed

- The rail, carriage, gate, drawer, and cartridges were polished physical
  metaphors, but they hid the software roles.
- Four equally abstract cartridges made the projects look interchangeable.
- The image could not answer the first recruiter question: what does the Agent
  call, what constrains it, and what durable result remains?
- Avoiding generic AI imagery became a stronger constraint than explaining the
  actual work.

The new scene keeps the tactile editorial material system but makes every large
object correspond to a real runtime role.

## Master scene

```text
Dynamics Atlas Agent Harness

  TaskPacket clamp          open harness chassis                    outputs
  + dataset pair   ->   Locator Agent / particle specimen   ->   EvidenceBundle
                              |       |       |                   or Block tray
                              v       v       v
                         registered tool ports
                              |       |       |
                              +-- six compatibility shutters --+
                                         |
                                  external human key

  brass trace tape records every proposed source, tool call, gate result,
  stop reason, and final review state.
```

### Physical objects

1. **TaskPacket clamp** — an ivory punched card held by a visible brass clamp,
   docked beside two transparent molecular-data plates. This is the input, not
   an ornamental cartridge.
2. **Open harness chassis** — a graphite frame with the control path exposed.
   Nothing important is hidden inside a mysterious black box.
3. **Particle specimen chamber** — the protein-fold and ligand point cloud is
   suspended in the centre. It is the scientific object translated into a
   computable representation.
4. **Locator carrier** — a small movable brass carriage may propose which
   source or missing input to use. It cannot cross the validation bank by
   itself.
5. **Registered tool ports** — three distinct, replaceable sockets under the
   chamber. A finite brass trace reaches only the tool that was actually
   invoked.
6. **Compatibility bank** — six narrow mechanical shutters in series. They
   represent the existing six compatibility checks without inventing their
   names in unreliable model texture text.
7. **Split output** — one open document cradle for an `EvidenceBundle` and one
   closed catch tray for a blocked route. Passing and stopping are equally
   visible outcomes.
8. **Human authority key** — a separate lever outside the automatic loop. The
   Agent cannot move it.
9. **Trace tape** — a narrow paper-and-brass loop along the front edge. It
   records the proposed route, tool calls, gate result, and stop or review
   state.

Exact role names remain selectable HTML overlays. The 3D mesh supplies form and
motion, not prose.

## Interaction

1. The chassis reveals once with the existing heading and portrait.
2. The TaskPacket seats; the brass locator carrier moves to the particle
   chamber.
3. Hover, focus, or pointer proximity pushes aside only nearby protein
   particles. They return to their stored positions when the pointer leaves.
4. Selecting a tool port draws one finite trace from Agent to Tool and back.
5. Running the default Dynamics profile closes the six shutters in order. The
   route ends in either the EvidenceBundle cradle or the Block tray.
6. Selecting a stage pauses the sequence and opens a literal HTML explanation:
   `Contract`, `Agent`, `Tool`, `Gate`, `Trace`, or `Human`.
7. Drag or arrow keys rotate the whole rig only within a restrained range. No
   free orbit, idle turntable, breathing loop, or page-wide particles.
8. Reduced-motion mode shows the final assembled state and keeps every stage
   selectable without particle physics.

## Connection to all four projects

| Profile | Input | Automated role | Harness / gate | Durable state |
| --- | --- | --- | --- | --- |
| Dynamics Atlas | TaskPacket + datasets | Locator Agent suggests a source | registered tools + six compatibility checks | EvidenceBundle or block |
| EvidenceOps | versioned passage | model extracts candidate fields | support match + human review | review record |
| HSP90 / LiGaMD | three replicas + assay-derived pKoff | ML workflow compares regressors | exact-ligand holdout + bootstrap | no selection on N31 |
| CarePlan | synthetic order | bounded AI worker generates a typed draft | rules + schema + reviewer role | review-pending state |

The default Hero render is the Dynamics profile. Later profile changes may
replace the centre representation and HTML copy, but they must also disable the
Agent station when the selected project is not an Agent. This makes role
differences visible instead of flattening all four systems into one AI story.

## Visual direction

- Three-quarter orthographic tabletop view, wide 3:2 composition.
- Open-frame industrial test rig rather than a sealed product or luxury desk
  accessory.
- Warm ivory paper, carbon graphite, smoked glass, porcelain, and oxidised
  muted brass. No blue-black, purple, red, cyan, or neon.
- The particle protein-ligand object is the only visually dense element. The
  frame around it stays spare and mechanically legible.
- One brass route is the only accent. It shows control flow rather than adding
  decorative glow.
- No text, logo, fake terminal, generic AI orb, robot, brain, neural-network
  web, or decorative grid baked into the image.

## Claim boundary

- The point cloud is a conceptual scientific object, not an experimental
  structure, simulation result, or model prediction.
- The Locator Agent proposes a route; registered tools and compatibility checks
  control whether it may run.
- `EvidenceBundle` and `block` are possible recorded states, not proof of a
  published or production deployment.
- The HSP90 profile remains scientific ML, EvidenceOps remains model-assisted
  evidence work, and CarePlan remains a synthetic controlled workflow.
