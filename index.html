01

Public MVP + local test build · Jun 2026—Present

EvidenceOps

Keep every scientific claim tied to the source that supports it.

Public MVP

EvidenceOps helps a researcher search public papers, extract a specific result, and carry the source, page, experiment conditions, and supporting text into review. If the cited passage does not support the claim, the system marks it unsupported instead of guessing. Its fixed synthetic test set passed 70/70 cases.

What I built

  • Stored each public source with its version and location, then combined keyword and vector search to find passages.
  • Extracted values, units, measurement type, experiment conditions, supporting text, and citation into a fixed structure.
  • Checked that the cited text supports the claim and that units and conditions match before sending it to review.

Why I designed it this way

Finding a relevant passage is only step one. A claim moves forward only when the cited text, unit, and experiment conditions match. Otherwise, the system returns “unsupported” instead of filling the gap from model memory.

Test result

70 / 70

The fixed synthetic test set covered 20 search cases and 50 extraction or validation cases.

What this does not prove

It uses public or synthetic inputs. These tests do not show production use, customer deployment, or scientific accuracy on open-ended research questions.

02

Synthetic workflow · Feb 2026—Present

CarePlan

Draft a pharmacy plan without giving the AI approval authority.

Local prototype

CarePlan moves a synthetic pharmacy order through rule checks, AI drafting, field validation, and pharmacist review. The AI can draft but cannot approve. All 200 permission and workflow-state checks passed; among 120 synthetic orders, 50 stopped at rules and 70 reached review.

What I built

  • Built a state machine that records each step from submission and drafting through review, approval, rejection, or reopening.
  • Made repeat submissions safe, restricted approval by role, recorded audit receipts, and limited retries after provider failure.
  • Checked every AI draft for required fields and valid workflow state before it entered the pharmacist review queue.

Why I designed it this way

The AI can write a draft, but it cannot approve one. Missing fields, serious conflicts, user permissions, and approval remain in server code.

Test result

200 / 200

All 200 permission and workflow-state checks passed. In 120 synthetic orders, 50 stopped at rule checks and 70 reached human review. Repeating the same request created one plan.

What this does not prove

Synthetic portfolio workflow only. No real patient data, clinical recommendation, autonomous approval, or production use.

03

Research-collaboration prototype · Jun 2026—Present

Dynamics Atlas

Check whether different molecular datasets can support the same analysis.

Validation prototype

Dynamics Atlas checks whether NMR ensembles, MD trajectories, and other molecular datasets are compatible before an analysis runs. It checks protein identity, residue mapping, conditions, data representation, and time coverage. The recorded implementation passed 13/13 harness tests, 24/24 machine checks, and 42/42 HSP90 replays.

What I built

  • Defined a structured task record that stores the requested analysis, source-file hash, decisions, output evidence, and run receipt.
  • Built separate analysis routes for different data types instead of forcing NMR ensembles and MD trajectories into one shared table.
  • Limited the Agent to suggesting evidence locations and missing inputs. Regular code still validates data, runs approved tools, and can block the task.

Why I designed it this way

On six exposed, retrospective development packets, the deterministic parser passed 6/6; a one-shot Agent and a tool-plus-one-repair Agent each passed 0/6 end to end. A deterministic compiler restored public-schema validity to 6/6, but only 1/6 met the evidence-level reviewer proxy. That result rejected direct Agent execution; it did not establish general Agent ability. I limited the model to suggesting evidence locations and missing checks.

Test result

13 · 24 · 42

13/13 harness tests, 24/24 machine validations, and 42/42 HSP90 output replays passed in the recorded implementation.

What this does not prove

These tests show that the workflow blocks invalid routes and records its output. They do not show that the Agent works well on new scientific tasks or that the scientific conclusions are correct.

04

UNC Miao Lab research · Jun 2025—Present

HSP90 / LiGaMD

Combine three simulation replicas without treating every frame as a new sample.

Public toolkit

For each protein-ligand system, I turn each of three LiGaMD replicas into its own 10-feature summary from 512 real saved frames, then average matching features across replicas to make one system record. I keep an exact ligand group entirely on one side of each train/test split. The registry has 31 systems and 27 ligand groups. The lowest MAE was 0.8182, but uncertainty did not support selecting a model.

What I built

  • Counted a ligand exit only when the geometry stayed past the threshold, with recapture handling so one distance spike did not count as dissociation.
  • Sampled 512 real saved frames from each passing replica and calculated a separate Dynamic10 vector, then averaged corresponding Dynamic10 values across replicas; Static20 and Dynamic10 form one row per system.
  • Kept exact copies of the same ligand in the same fold and fit preprocessing only on training data to reduce leakage.

Why I designed it this way

One model had the lowest average error, but its uncertainty overlapped the baseline. I report that result without calling it a selected or final model.

Frozen registry

N31 / 27 groups

The current registry contains 31 systems and 27 exact-ligand groups. The lowest group-equal MAE was 0.8182; uncertainty did not support model selection.

What this does not prove

The target is experimental pKoff measured in assays. The simulation does not directly produce a physical dissociation rate, and this 31-system dataset does not support a final model or broad generalization.

How I work

I separate model output, software checks, and human decisions.

A model can return the wrong format, time out, or make an unsupported claim. In my projects, it cannot directly change a record or approve a result. The software saves each check and workflow state so a failed run can be inspected and resumed.

01

Give the AI clear rules.

The model receives a defined input and approved tools. It cannot approve its own output.

02

Save the workflow state.

When a model times out or returns invalid data, the failure is recorded so work can resume without starting over.

03

Use the right unit for evaluation.

I split data by an independent unit, such as a document, user, ligand, or system, to reduce leakage.

04

Report exactly what the test covered.

A local test can verify a defined behavior. It does not by itself prove production readiness, scientific accuracy, or real-world impact.

Human ownership

I use AI-assisted coding, but I remain responsible for defining the problem, choosing the architecture, reviewing failures, and deciding what the results support.
